# ajiro

低インタラクション型ハニーポットで攻撃ログを集め、自作のコレクターとダッシュボードで可視化する——つもりで作り始め、**デプロイ前に開発を中止した**プロジェクトです（2026-10-28）。

**セキュリティの学習を目的として作成したものです。**

ハニーポットは一度もインターネットに公開していません。このリポジトリに観測データは含まれていません。動くサービスとしてではなく、**設計判断とガードレールの記録**として公開しています。

## 中身

| パス | 内容 | 状態 |
|---|---|---|
| `cmd/webpot`, `internal/webpot` | Go 製の Web ハニーポット。リクエストを記録して定型レスポンスを返すだけ | ローカルで動作確認済み |
| `deploy/webpot/Dockerfile` | webpot のコンテナ（非 root、cgo なし） | 未使用 |
| `cmd/shipper`, `internal/shipper` | ハニーポット上のログを tail してコレクターへ一方向 push | ローカルで結合確認済み |
| `cmd/collector`, `internal/collector` | 受信・スキーマ検証・JSONL アーカイブ・DuckDB 格納・読み取り専用クエリ API | ローカルで結合確認済み |
| `cmd/query` | DuckDB を読み取り専用で開く確認用ツール | — |
| `dashboard/` | TanStack Start + Solid 2.0 RC の自分専用ダッシュボード（概要・時系列グラフ） | 骨組みのみ |
| `internal/guardrail` | 下記の安全方針をテストとして機械的に検査する | — |
| `HANDOFF.md` | 設計資料。決定事項・セキュリティ設計・リスク評価（プレモーテム）・公開関門 | 中止時点のまま |

SSH 側（Cowrie）、VPS の構築、SSE のライブ表示などは手を付けていません。

## 安全に関する前提

設計の原則は「問題は入ってくる攻撃ではなく、**出ていくもの**」です。詳しくは `HANDOFF.md` §4・§11 を参照してください。

- **低インタラクション型のみ**。本物の OS を晒す高インタラクション型はやらない（踏み台にされたときの加害責任を負わないため）
- **ハニーポットの外向き通信（egress）は完全遮断**。例外はコレクターの ingest 宛て（IP 直指定、DNS も使わない）だけ。攻撃者が指定した URL を取得しに行くことは構造的にできない
- **プロキシとして動かない**。`CONNECT` や絶対 URI 形式のリクエストは記録だけして転送しない
- **マルウェア検体を保存しない**。URL とハッシュ（得られる場合のみ）だけを記録する
- **受け取ったペイロードは実行・評価しない**
- **ログの中身はすべて攻撃者が書いた文字列として扱う**。SQL はパラメータ化、画面では `innerHTML` を使わず制御文字を記号化、URL はリンク化しない
- ダッシュボードは公開しない（`127.0.0.1` 待ち受け）。目印付きの文字列を送られるとセンサーを特定されるため

このコードを参考に自分で運用する場合も、上記（特に egress の遮断）はコードだけでなくファイアウォールで担保してください。

## AI エージェントと作るためのハーネス

実装の大部分は Claude Code（AI コーディングエージェント）が書きました。エージェントが安全方針を破らないよう、指示文（`CLAUDE.md`）に加えて、機械的な検査を何層かに分けて置いています。

- `internal/guardrail`：`os/exec` などの禁止パッケージ、ハニーポット側の外向き通信の経路、ダッシュボードでの `innerHTML` などを静的に検査するテスト
- `.githooks/pre-commit`：データや秘密ファイルのコミット拒否、gitleaks、ガードレールテスト
- `.claude/settings.json`・`.claude/hooks/guard-bash.sh`：秘密ファイルの読み取り禁止、ガードレール関連ファイルの変更や観測データの読み取りには人間の確認を必須にする（観測データは攻撃者の文字列で、エージェントへのプロンプトインジェクションになりうるため）、pre-commit の回避・force push・公開操作の禁止
- `.claude/agents/guardrail-reviewer.md`：コミット前に、別コンテキストでステージ済み差分をガードレールと照らし合わせるレビュー担当

いずれも事故防止のための粗い検査で、意図的な回避は防げません。既知の抜けは `HANDOFF.md`（横断：エージェント向けハーネス）に書いています。

## 動かす

```sh
git config core.hooksPath .githooks   # pre-commit を有効化（gitleaks が必要）
go test ./...                         # ガードレールテストを含む
```

collector は cgo（DuckDB）が必要です。webpot と shipper は標準ライブラリのみで、cgo なしでビルドできます。
